# Linting and the push checklist

What has to be green before a task is done and before every push. The task-level recipe
(exact tasks, the Stylelint and ESLint rules that bite, the auto-fix) is the `lint-gate` skill.

- **Every new or modified piece of code must be linted before the task is considered done.** Run at least `./gradlew :<module>:checkstyleMain :<module>:spotbugsMain` (or `./gradlew check` for the full sweep) and read the reports.
- **All Checkstyle and SpotBugs errors *and* warnings introduced or touched by your change must be fixed.** Do not silence findings with `@SuppressWarnings`, `@SuppressFBWarnings`, or Checkstyle suppression files unless the rule is genuinely wrong for that specific call site — and in that case the reason goes into `@SuppressFBWarnings(justification = "…")` where the annotation has that attribute, otherwise into the commit message and the PR, never into a comment (ADR-0214).
- Pre-existing findings in code you did not touch are out of scope; do not opportunistically clean them up in an unrelated change. But never *add* a new finding on top of them.
- **One command formats the repository** (REQ-OPS-058, ADR-0390). `./gradlew spotlessApply` rewrites and `./gradlew spotlessCheck` checks every file a formatter owns: Java in every source set (google-java-format), the Gradle Kotlin scripts and `build-logic` (ktfmt), JSON (Gson), Python (Ruff, settings in `ruff.toml`), the shell scripts and `.githooks/*` (shfmt, settings in `.editorconfig`), the CSS and JS of the frontend, the Keycloak theme and `docs/exchange/assets` (Prettier, `.prettierrc.json`), and whitespace and the final newline of YAML, Markdown and `.properties`. Ruff and shfmt are verified release binaries that Gradle installs under `build/tools/` on first use; do not run another version of them, or Prettier with other options. A file no formatter owns follows `.editorconfig`.
- **The push gate.** Set `git config core.hooksPath .githooks` once per clone (every worktree of the clone shares it; Claude Code's `SessionStart` hook sets it). `.githooks/pre-push` runs `./gradlew spotlessCheck` on the working tree and refuses a push that carries commits while it fails. Do not bypass it with `--no-verify`; CI fails the same files anyway.
- **Run `./gradlew spotlessApply` (whole repo) locally before *every* push — no exceptions, even for a one-line test or comment edit**, and **ALL** lint tasks must be green before *every* push. Formatting alone is **not sufficient**: the frontend's `check` also runs strict asset gates — Stylelint (`:frontend:lintCss`, `:frontend:lintCssInline`), ESLint (`:frontend:lintJs`, `:frontend:lintProbeJs`), HTMLHint (`:frontend:lintHtml`) — plus the static type check `:frontend:typecheckJs` (REQ-FE-018, ADR-0125) and the exchange developer pages' gate `:frontend:checkExchangeDocs` (no German text, every relative link resolving, markdownlint with 100-character lines — tables and code exempt — the DPoP reference tests; REQ-XCH-002), and the root project's `ruffLint` (`ruff check` with Ruff's default rules over every Python file `ruffFormat` owns; REQ-OPS-060), all of which fail CI independently and are not covered by Spotless/Checkstyle. Never push relying only on the tests + Spotless being green. Exact tasks, the Stylelint/ESLint rules that bite, and the auto-fix recipe: the [`lint-gate`](../../.claude/skills/lint-gate/SKILL.md) skill.
